# Ink 钱包资金交接

入口：钱包总览左侧“资金交接与小额测试”，或同一个浏览器打开 `http://127.0.0.1:18270/funds`。页面需要解锁保险库并选择 Ink 主网。

## 当前交付范围

- 可执行：1 号 → 2 号 → 3 号 → 1 号，每笔 1 USDT0 的一次循环，由操作者核对后启动。
- 可规划：上一批与下一批直接一一对应；钱包数、来源、目标范围可以修改。批次规划不可执行，等待交易策略确定后接入。
- 已预留策略接口 `queueHandoffAfterTrading`：接收明确的交易与结算完成事件，只持久化待检查计划，不自动签名或广播。
- 当前不平仓、不提现、不为下一批存入 Nado，也不把批量下单任务的“提交完成”当作交易结束。

## 为什么 2、3 号可以没有 ETH

Ink 主网 USDT0 合约支持 EIP-3009。持币钱包在本地签署限定收款人、金额、随机授权序号和短有效期的授权；1 号资金库签署并发送链上交易，支付 ETH 手续费。USDT0 从持币钱包直接进入收款钱包，不经过资金库中转。

这只涵盖本功能的 USDT0 授权转账。普通钱包的“发送”、其他代币或 Nado 的链上充值，并不会因此自动变成由资金库付 Gas。

USDT0 精度为 6 位，普通钱包间可以转 1 USDT0；这与 Nado 的首次入金门槛无关。资金库支付的 ETH 与转出的 USDT0 分开扣除。

## 小额验收

1. 固定使用同一个浏览器配置及 `127.0.0.1:18270`，解锁后进入资金交接页，切换 Ink 主网。
2. 选择“先测试 1 USDT0”，点击“预检并查看完整地址”。核对 1、2、3 号完整地址，1 号至少持有 1 USDT0 和手续费预算，2、3 号的 ETH 为 0。
3. 查看只读模拟的参考费用与填写的手续费上限。参考值来自临时随机账户的虚拟余额，不会使用正式钱包签名或发送资金；节点不支持模拟时会明确显示报价不可用。
4. 勾选地址、金额与预算确认，再点击“启动 1 USDT0 循环测试”。每笔完成链上核验后才执行下一笔。
5. 应看到 3/3 笔到账，1 USDT0 回到 1 号，2、3 号转出前后的 ETH 仍为 0。核对实际费用、哈希和等待时间，导出 CSV 或 JSON。

实际费用使用 `gasUsed × effectiveGasPrice + l1Fee`，没有 L1 费用字段的回执不会被记成 0 费用。页面保留链上区块时间及本机发送、核验时间；“等待秒数”是本机从首次提交到核实到账的时长，包含轮询、网络延迟和中断时间，不是承诺的链上速度。本版等待两个 L2 区块确认，不等同于以太坊最终确定性。

每笔与整批预算在发送前核对。L2 费用受签名交易的 Gas/价格上限约束；L1 费用使用当前估算及预留空间，实际 L1 费用仍会随网络变化。最终以回执为准，报价不是固定收费。

## 防重复与恢复

任务、授权随机序号、限定的授权签名、原始交易字节及本地计算的交易哈希按顺序写入当前浏览器的 IndexedDB，写入失败就不继续发送。首次广播时间也先写入，网络超时不会重置计时。

- 双击、同一批次标识重复创建、同源同浏览器的多个标签页并发启动会被拦截。
- 离开页面或切换网络会请求暂停；已广播的交易无法取消，恢复先查询原交易。
- 重开页面不自动继续。点击“核对原交易并恢复”，优先读取原回执或匹配的授权与转账事件，只能重发相同交易字节，不生成第二份付款授权。
- 过期、执行失败、无法确定原交易结果、余额异常等情况保留原任务并停止后续转账，不能通过另建测试来跳过核验。
- 导出报告不包含可执行的签名或原始交易，报告也不能代替本地恢复记录。不要清除浏览器站点数据或用另一浏览器另起同一任务。

跨标签页锁只覆盖同一浏览器配置和同源页面，不能锁住 MetaMask、其他浏览器、其他端口或外部脚本。执行期间不要从这些入口同时使用资金库发送其他交易。准备和恢复都会复查资金库交易序号，发生变化时停止，不会自动换新序号再付款。

## 直转与汇总如何选择

假设 N 个来源钱包交接给 N 个新钱包，且没有地址重叠：

| 方案 | 普通逐笔转账数 | 适用情形 |
| --- | ---: | --- |
| 一一对应直接转 | N | 下一批沿用上一批各钱包的可用金额 |
| 汇总到资金库，再逐笔分发 | 通常约 2N | 需要将盈亏后的余额重新均分、改变钱包数量或保留统一储备 |

因此先采用直接交接作为候选默认路线。它省掉中转，但不能把“交易数减半”直接当成“费用恰好减半”：收款地址首次持币、授权处理、批量调用等都会改变 Gas。原生批量分发可减少交易数量，但仍有逐个账户记账成本，本版没有启用。后续用实际钱包状态模拟每条路线，比较总费用、排队时间和失败恢复成本后再选策略。

当前测试为逐笔确认，便于核验。未来不同配对可以在资金库统一管理交易序号的前提下适度并发；一条循环链仍需等上一步到账。钱包数、单次交接金额、并发度、是否汇总、何时开始下一轮交易均待策略讨论，不在本版写死。

未来执行条件是：策略发出持久化的结算完成事件 → 无仓位/挂单 → 资金实际回到链上 → 规划与费用核验 → 签名及发送 → 核验到账 → 下一批。现有 `bulk` 只提交订单，未接到此入口。

当前仓位检查覆盖控制台使用的 `default` 子账户及其隔离仓位；其他命名子账户尚未纳入。批次执行开放前，还需结合最终策略验证全市场挂单查询、资金回链与下一批入金，不据此认定钱包名下所有子账户均已结算。
